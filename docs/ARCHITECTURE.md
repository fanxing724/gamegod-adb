# 结构与状态恢复

应用包名 `cn.fanxing.starplay`，独立安装，不覆盖荣耀系统游戏管家。

## 模块

| 文件 | 职责 |
| --- | --- |
| MainActivity | 游戏库、逐游戏策略、一次性授权、恢复入口与能力边界 |
| ModeSession | 不依赖 Android 的游戏模式事务；先保存原值再写系统，失败保留记录 |
| DeviceControl | Secure 游戏模式读写、持久化恢复记录、荣耀设备限制 |
| SessionActions | 协调游戏模式恢复和可选的系统电池策略恢复 |
| SessionService | 用户游戏会话前台服务、通知、可拖动入口、游戏内工具面板 |
| DeviceMonitor | 内存/网络/电量、受限的 CPU 与 SurfaceFlinger 呈现帧采集 |
| MonitorMath | CPU、真实呈现时间戳和流量计数解析；纯 JVM 可测 |
| BatteryAutomation | 可选辅助功能；只操作荣耀系统电池页的精确性能开关 |

## 游戏模式事务

```text
读取原值 → 同步保存恢复记录 → 写候选模式 → 读回确认
结束时：对比当前值 → 恢复原值 → 读回确认 → 清除记录
```

- 进入前没有该设置，恢复时删除该设置，不擅自写默认值。
- 外部变化时拒绝覆盖，保留记录供用户决定。
- 变更模式前保存旧目标值，以覆盖写入中断/失败的恢复场景。
- `keepCurrentAndEnd` 必须由用户明确选择。
- 没有开机自动修改模式或无限期巡检。监测仅在用户会话期间运行。
- 当前需要手动结束会话。跟随系统只启动应用，不建立调度会话。

## 监测与资源约束

- 系统内存：ActivityManager.MemoryInfo；可用内存不是立即闲置的物理内存。
- 网络：ConnectivityManager 的类型与验证状态；TrafficStats 全设备收发计数差分，不能称为游戏网速或游戏延迟。VPN 可能影响计数含义。
- 电量与温度：系统电池广播，温度为电池温度，不冒充 CPU 温度。
- CPU：App 自己的 UID 执行受限 `dumpsys cpuinfo`，需 DUMP 与使用情况访问权；系统采样窗口不是精确瞬时游戏进程占用。不可读时不伪造数值。
- FPS：仅解析目标游戏 SurfaceFlinger 图层的实际呈现时间戳，近 2 秒估算；忽略 0、重复、过期、未来时间戳和 Long.MAX_VALUE。首行刷新周期绝不能当作 FPS。
- 未获权限、固件不返回近期帧或匹配不到图层时显示待授权/不可用。
- 系统诊断进程使用固定参数 ProcessBuilder，无 su/adb/shell 拼接，无任意命令执行入口；每次超时与输出大小有界。
- 单独后台工作线程；面板展开约 2 秒、折叠约 5 秒采样，图层重新搜索有节流；不持有唤醒锁。

## 系统电池性能模式

这是与游戏模式分开的状态。直接写 SmartModeStatus 不能被当作完整系统切换。

可选辅助功能在用户授权后：

1. 记录进入前策略；只适配已核实的系统智能/性能状态。
2. 打开系统电池页。
3. 查找 `com.hihonor.systemmanager:id/perform_mode_switch`。
4. 只在目标值不同时点击该控件。
5. 同时核对原生勾选状态与 Settings 状态后，再返回游戏。
6. 结束/切回均衡时，恢复原来的电池策略；外部改值冲突时保留记录。

事件限定为系统管家包；没有聊天读取、手势注入、通用确认按钮点击逻辑。18 秒超时，失败显示错误并保留恢复记录。服务被关闭或 App 被清除后不能保证自动恢复；主界面有独立电池恢复卡片。卸载前必须结束会话并恢复策略。

## 清理运行内存

Android 14+ 普通应用的 killBackgroundProcesses 仅能清理自身进程。本项目不展示虚构“已释放 XX MB”，不批量 force-stop 用户应用。面板把清理交给荣耀系统管家，实际执行和确认在系统页面完成。
